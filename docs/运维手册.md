# AI 芯动力 官网 · 运维手册

> 面向对象：社团内容维护者（不需要会写代码）。
> 原则：**你只改 `content/` 里的 JSON 和 Markdown，其余交给 GitHub Actions。**

---

## 0. 一分钟速查

| 我想做的事 | 改哪个文件 | 大概多久生效 |
|---|---|---|
| 发布/更新一个活动 | `content/events.json` | 提交后 2 分钟 |
| 加一条学院资讯 / 竞赛信息 | `content/events.json` | 提交后 2 分钟 |
| 加一份资源库资料 | `content/resources.json` | 提交后 2 分钟 |
| 改合作伙伴状态 | `content/partners.json` | 提交后 2 分钟 |
| 改联系方式、QQ 群、报名表链接 | `content/site.json` | 提交后 2 分钟 |
| 写一篇活动详情长文 | `content/pages/<活动id>.md` | 提交后 2 分钟 |
| 改活动预告文案 / 组织架构 / 项目方向 | 对应 `content/*.json` | 提交后 2 分钟 |
| 改站点颜色、字号、间距 | `assets/css/style.css` 顶部 `:root` | 提交后 2 分钟 |

生效时间取决于 GitHub Actions 排队情况，通常 90 秒到 3 分钟。可以到仓库
**Actions** 标签页看「Deploy website to GitHub Pages」这条工作流的状态。

## 1. 网站是怎么跑起来的

```
你改 content/*.json（内容）          ← 只碰这里
          │
          │ 本地跑一次 python3 scripts/build.py
          │ 再 git commit + push 到 main
          ▼
GitHub Actions（.github/workflows/pages.yml）
  把仓库里 dist/ 目录发布为 Pages 产物
          │
          ▼
https://uestc-aic.github.io/         ← 约 1-3 分钟上线
```

> **当前处于「手动构建」模式**：改完内容需要本地跑一次 `python3 scripts/build.py`
> 并一起提交 `dist/`。
> 想省掉这一步（让 Actions 自动构建），见 [§12 启用自动构建](#12-启用自动构建推荐)。

另一条线：`collect.yml` 每天定时运行 `scripts/collect.py`，
抓取校级公开信息源，把新条目写进 `content/collected/`，
如果抓到了新东西就自动提交一次，从而触发上面的构建。

**关键点：`dist/` 是产物，不要手动改它。** 改 `content/` 和 `assets/`，重新构建即可。

### 目录职责

| 目录 | 谁维护 | 说明 |
|---|---|---|
| `content/` | **内容维护者** | 所有会变的内容。JSON + Markdown |
| `content/collected/` | 采集脚本（自动） | 自动抓来的条目，人工不要手改 |
| `content/inbox/` | 投稿者 | 未整理的人工投稿，编辑审核后搬到 `content/` |
| `assets/` | 视觉维护者 | CSS / JS / 图片。改样式只改 `style.css` 的 `:root` |
| `scripts/` | 技术维护者 | 构建器与采集器 |
| `docs/` | 技术维护者 | 本手册与采集系统说明 |
| `sources/` | 技术维护者 | 采集源配置 |
| `dist/` | **自动生成** | 不要手改 |

## 2. 最常见操作：发布一个活动

### 2.1 直接改 JSON（推荐，适合一次性发布）

打开 `content/events.json`，在 `items` 数组**最前面**加一条：

```json
{
  "id": "salon-01",
  "category": "salon",
  "status": "upcoming",
  "featured": true,
  "title": "第一期芯沙龙",
  "titleEn": "THE FIRST CONNECTION",
  "vol": "VOL. 01",
  "dateText": "11月20日 周四 19:00",
  "time": "19:00–21:00",
  "location": "科研楼 A 栋 305",
  "organizer": "AI 芯动力（UESTC AIC）",
  "speakers": [
    { "role": "主讲", "name": "张三", "title": "2024级", "org": "集成电路科学与工程学院" }
  ],
  "summary": "一句话说明，会显示在卡片上，控制在 40 字以内。",
  "topics": ["议题一", "议题二"],
  "tags": ["AI × IC"],
  "registerUrl": "https://你的报名表链接",
  "body": "salon-01.md",
  "locked": true,
  "source": null,
  "links": [
    { "label": "活动推文", "url": "https://mp.weixin.qq.com/s/xxxx" }
  ]
}
```

### 2.2 字段含义（照抄即可）

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `id` | ✅ | 英文小写 + 连字符 | **唯一**，也是详情页网址：`events/<id>/` |
| `category` | ✅ | `salon` / `regular` / `campus` / `competition` | 活动分类，决定筛选归属 |
| `status` | ✅ | `tbd` / `upcoming` / `ongoing` / `past` | 待定 / 即将开始 / 进行中 / 已结束 |
| `featured` | | `true` / `false` | 首页优先展示（一般只给一个） |
| `title` | ✅ | 中文标题 | 卡片与详情页标题 |
| `titleEn` / `vol` | | 字符串 | 详情页页头的英文小标注 |
| `dateText` | | 字符串 | 显示用日期，**没确定就写 `待公布`** |
| `time` / `location` | | 字符串 | 没确定写 `待公布`，页面会高亮成橙色"待公布" |
| `organizer` | | 字符串 | 默认「AI 芯动力（UESTC AIC）」 |
| `speakers` | | 数组 | 每项 `{role, name, title, org}` |
| `summary` | ✅ | 一句话 | 卡片描述，≤40 字最好看 |
| `topics` | | 字符串数组 | 议题 / 候选主题 |
| `tags` | | 字符串数组 | 标签 |
| `registerUrl` | | https 链接 | 报名表；空着会显示「关注后续通知」 |
| `body` | | 文件名 | 指向 `content/pages/<文件名>`，写长文用 |
| `locked` | | `true` / `false` | **`true` = 人工维护，采集脚本永不覆盖** |
| `source` | | `null` 或 `{name,url}` | 采集来源，人工录入填 `null` |
| `links` | | 数组 | 附加链接，每项 `{label, url}` |

### 2.3 发布前自检（很重要）

- `id` 不能和已有的重复（重复构建会报错）
- `category` 和 `status` 只能用上表里的值（写错构建会报错）
- 所有 URL 必须是 `https://` 或 `http://` 开头
- JSON 里**不能有多余的逗号**（最后一项后面不能加 `,`）
- 中文引号 `""` 不能当 JSON 的引号用，必须用英文 `"`

### 2.4 本地自检命令

```bash
python3 scripts/build.py --check     # 只校验内容，不生成
```

有问题的条目会一条条列出来，一次改完。**建议提交前跑一次。**

## 3. 写一篇活动详情长文

1. 在 `content/pages/` 新建 `<活动id>.md`，例如 `salon-01.md`
2. 用 Markdown 写，支持：`##` `###` 标题、段落、`-` 列表、`1.` 列表、
   `**加粗**`、`[文字](链接)`、`>` 引用、`| 表格 |`、`---` 分隔线
3. 在 `content/events.json` 里把该条活动的 `body` 设为 `"salon-01.md"`

> 图片：放到 `assets/img/` 下，Markdown 里写 `![说明](../assets/img/xxx.png)`。

## 4. 加一条资源库资料

打开 `content/resources.json`，在 `items` 里加：

```json
{
  "id": "openroad",
  "title": "OpenROAD",
  "titleZh": "开源数字芯片设计全流程",
  "category": "eda-tool",
  "description": "从 RTL 到 GDSII 的完整开源实现流程，适合想了解工业界真实设计链路的学生。",
  "source": "The-OpenROAD-Project/OpenROAD",
  "url": "https://github.com/The-OpenROAD-Project/OpenROAD",
  "stars": 2400,
  "language": "C++",
  "license": "Apache-2.0",
  "level": "进阶",
  "tags": ["开源EDA", "数字后端"],
  "verified": "2026-10-15",
  "http_status": 200
}
```

`category` 只能取：

| 值 | 页面显示 |
|---|---|
| `ai4eda` | AI for EDA |
| `ic-design` | IC 设计 |
| `eda-tool` | EDA 工具 |
| `ai-agent` | AI / Agent |
| `course` | 课程教程 |
| `paper-list` | 论文清单 |
| `dataset-model` | 数据集/模型 |
| `workflow` | 工作流 |
| `community` | 社区竞赛 |

`level` 只能取 `入门` / `进阶` / `研究`。

> **投稿要求：`url` 必须是你亲手点开确认能访问的。** 添加后请把 `verified`
> 写成本次确认日期，`http_status` 写实测状态码（200 为正常）。

## 5. 学院资讯与竞赛信息

### 5.1 自动采集（覆盖校级公开源）

每**天**定时运行一次，抓到的内容进入 `content/collected/`。
不需要人工干预，只管用。

已接入的源见 `sources/sources.json`。采不到的情况有两种：

- **源失效**：学校网站改版，选择器对不上了。表现为连续多天抓取数为 0。
  修法见 `docs/采集系统说明.md`。
- **源本身抓不到**：例如**集成电路科学与工程学院官网 `icse.uestc.edu.cn`
  装了 JS 挑战型 WAF，程序直连一律返回 HTTP 412**，自动化抓取不可行。
  这类内容只能靠人工投稿 —— 见下一条。

### 5.2 人工投稿（覆盖学院内部信息）

学院内网通知、班级/课题组层面的消息，走人工：

1. 投稿人按格式提交：

   ```
   资料标题：
   原始链接：
   内容简介：
   适合人群：
   ```

2. 维护者把它整理成 `content/events.json` 里的一条，`category` 填 `campus`
   或 `competition`，`locked` 填 `true`，`source` 填 `null`，
   `links` 里放原文链接。
3. 提交，1–3 分钟上线。

> `locked: true` 的意义：自动采集**永远不会覆盖**这条。人工修正过的信息
> 不会被下一次采集改回去。

### 5.3 手动补一条采集不到的通知（快速法）

```json
{
  "id": "campus-20261120-lecture",
  "category": "campus",
  "status": "upcoming",
  "title": "关于举办 XX 学术讲座的通知",
  "dateText": "2026年11月20日",
  "location": "科研楼 A305",
  "summary": "讲座题目与主讲人简介。",
  "locked": true,
  "source": null,
  "links": [
    { "label": "原文链接", "url": "https://icse.uestc.edu.cn/info/1057/xxxx.htm" }
  ]
}
```

## 6. 改站点全局信息

`content/site.json`：

```json
{
  "qqGroup": "https://qm.qq.com/q/xxxx",          // 填了加入页自动显示可复制入口
  "joinForm": "https://你的招新报名表",            // 填了「加入我们」出现按钮
  "contributeForm": "https://你的投稿表单",        // 填了投稿页出现按钮
  "salonRegisterForm": "https://沙龙报名表",       // 沙龙详情页的报名按钮
  "email": "contact@example.com"
}
```

**留空是安全的**：页面会显示明确的「待公布」占位，不会出现死按钮。
填上链接后按钮自动出现，不需要改任何 HTML。

`nav` 数组控制顶部导航，增删项即可（`href` 是相对仓库根目录的路径）。

## 7. 改样式

只改 `assets/css/style.css` 顶部的 `:root`：

```css
:root {
  --bg: #fafbf6;        /* 页面背景（暖米白） */
  --text: #203d32;      /* 主文字（深松绿） */
  --accent: #355c43;    /* 主强调色（按钮、链接、活跃态） */
  --accent-soft: #d6e6b7;  /* 高光（标签、选中背景） */
  --radius: 12px;       /* 卡片圆角 */
}
```

**不要**在组件里写死颜色值。设计规范全文见仓库根目录 `DESIGN.md`，
里面写清了「什么能做什么不能做」（禁止霓虹渐变、禁止卡片投影、禁止 emoji 当图标等）。

## 8. 出问题怎么查

| 症状 | 原因 | 处理 |
|---|---|---|
| 提交后页面没变 | Actions 还在跑 / 失败了 | 仓库 Actions 标签页看红色 ✗，点进去看日志 |
| 页面显示 404 | 该 `id` 没有生成详情页 | 检查 `content/events.json` 里有没有 `id` 字段 |
| Actions 报「不是合法 JSON」 | JSON 语法错 | 用 `python3 scripts/build.py --check` 本地查，通常是多余逗号或中文引号 |
| Actions 报 category 非法 | 分类值写错 | 见 §2.2 表格 |
| 链接点开是空白 | `url` 少了 `https://` | 补全 |
| 采集连续几天 0 条 | 源改版了 | 见 `docs/采集系统说明.md` 的「源失效」一节 |
| 页面样式错乱 | CSS 改坏了 | `git revert` 上一个提交，或对照 `DESIGN.md` 检查变量名 |

**紧急回滚**：在仓库里找到最后一个正常提交，Actions → 该 commit → Re-run，
或者本地 `git revert <坏提交的hash>` 再 push。

## 9. 权限管理

| 角色 | 权限 | 能做什么 |
|---|---|---|
| Owner | Admin | 全部，包括改仓库设置、加协作者 |
| 内容维护者 | Write | 推送 `content/`、`assets/`、`docs/` |
| 投稿者 | 无仓库权限 | 通过投稿表单 / GitHub Issue 提交，由维护者录入 |

加人：仓库 **Settings → Collaborators and teams → Add people**，权限选 **Write**。

> Write 权限可以推送 `.github/workflows/` 以外的任何文件。要改工作流文件，
> 推送者的 token 需要额外的 `workflow` 权限（`gh auth refresh -h github.com -s workflow`）。

## 12. 启用自动构建（推荐）

当前 `dist/` 需要本地构建后提交。启用下面的升级后，**你只需要改 `content/` 并提交，
Actions 会自动构建并发布**，`dist/` 不再需要进仓库。

### 为什么现在没开

推送 `.github/workflows/` 下的文件需要一个额外的 `workflow` 权限，
而当前维护账号的 GitHub 令牌没有这个权限（GitHub 会直接拒绝，报 404 / 403）。
这不是仓库设置问题，是令牌权限问题。

### 升级步骤（维护者操作，约 1 分钟）

1. 在本机终端执行，按提示在浏览器里点一次授权：

   ```bash
   gh auth refresh -h github.com -s workflow
   ```

2. 让管理员把仓库里**已备好的新版工作流**推上去（内容已随仓库提交，无需你手写）：

   ```bash
   git push origin main
   ```

   推送后仓库会多出 `.github/workflows/collect.yml`，
   且 `pages.yml` 会变成「校验内容 → 构建 → 发布」三步。

3. 把 `.gitignore` 里的 `# dist/` 改成 `dist/`，然后：

   ```bash
   git rm -r --cached dist
   git commit -m "chore: dist/ 交给 CI 构建"
   git push
   ```

### 升级后你会得到

- **改 JSON → 提交 → 自动上线**，不用再本地构建
- **内容校验门禁**：`content/` 里写错分类、缺 id、链接不是 http(s)，
  Actions 会直接失败并指出哪一条有问题，坏数据不会上线
- **每日自动采集**：每天北京时间 03:10 自动抓取 `sources/sources.json` 里启用的源，
  有新条目就自动提交并触发重新发布

### 只想先要采集、不想改构建方式

也可以只推 `collect.yml`。采集结果会写进 `content/collected/`，
但你仍需本地跑一次 `python3 scripts/build.py` 并提交 `dist/` 才能看到新内容。

## 13. 推送（重要：本机 `git push` 会被墙）

本机到 `github.com:443` 的连接会被干扰，`git push` 会卡住并报
`Failed to connect to github.com port 443`。**但 `api.github.com` 是通的。**

所以本仓库提供一个等效的推送脚本，用 GitHub Git Data API 完成一次原子提交：

```bash
python3 scripts/push_via_api.py --dry-run --message "看看会改什么"   # 先看清单
python3 scripts/push_via_api.py --message "更新活动日历"
```

它做的事和 `git push` 一样：把工作区文件差异做成**一个提交**推到 main。

**注意两点：**

1. 它**不会动 `.github/workflows/`**（没有 workflow 权限时 API 会拒绝，脚本会跳过并提示）。
   这很重要——脚本已经做了保护，不会误删工作流文件。
2. 它不做合并。如果别人在你之后推了新提交，先确认远端状态：

   ```bash
   gh api /repos/uestc-aic/uestc-aic.github.io/commits --jq '.[0:3][] | "\(.sha[0:8])  \(.commit.message | split("\n")[0])"'
   ```

   有你不认识的提交时，先 `git pull`（若也被墙，就用
   `gh api /repos/uestc-aic/uestc-aic.github.io/tarball > /tmp/repo.tgz` 取回最新代码）。

### 网络正常时

如果哪天 `github.com` 能连上了，直接用原生的：

```bash
git add -A && git commit -m "..." && git push
```
